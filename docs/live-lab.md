# Настоящая лаборатория по ссылке

Есть два разных способа открыть реальные Axum + PostgreSQL + OpenFGA без VPS.
Ни один не является обещанием круглосуточного production-hosting.

## Личный Codespace

Используйте кнопку в README и ветку с `.devcontainer/devcontainer.json`.
Codespace создаётся самим пользователем. При просмотре изменений до слияния
выберите соответствующую ветку PR; после слияния используйте `main`.

Сервис автоматически запускается через postStart. Откройте **Ports → 3000**;
GitHub требует вход владельца для приватного порта. postAttach явно выставляет
`3000:private`; ошибка этой команды не подавляется. Не меняйте видимость на
Public. Остальные порты не форвардятся автоматически; контейнеры PostgreSQL и
OpenFGA не публикуют host-порты.

В своём Codespace:

```sh
cat .lab/codespaces/secrets/demo-password
bash scripts/codespace-lab.sh status
bash scripts/codespace-lab.sh verify
bash scripts/codespace-lab.sh stop
bash scripts/codespace-lab.sh start
```

Пароль случайный, отдельный для этого Codespace, используется пятью
вымышленными demo-аккаунтами. Не отправляйте его в issue. Start не перезаписывает
секреты и не сбрасывает изменённые пользователем права; первичная приёмка
выполняется только при первом создании состояния. Повторный start пересобирает
приложение и кратко останавливает его и OpenFGA перед миграциями; тома и пароли
сохраняются. Verify использует lab-tool работающего образа, а не старый image ID
из первоначального env-файла. Он ожидает исходное состояние таблицы `requests` и меняет её
тестовые права, поэтому не запускайте его одновременно с ручной выдачей доступа.
Stop сохраняет тома. Удалённый Codespace не является резервной копией.

Devcontainer использует отдельный Docker-in-Docker daemon и не монтирует
Docker socket чужого хоста. Его privileged-режим необходим DIND и ограничен
вашим devcontainer/VM; это не способ изолировать недоверенный код от оператора
этой VM. Не помещайте сюда реальные данные или production-секреты.

Codespaces расходует квоту владельца окружения, сверх квоты возможна оплата.
README-кнопка не создаёт платное окружение без действия пользователя.
Официальные сведения: https://docs.github.com/en/billing/concepts/product-billing/github-codespaces
Приватные порты: https://docs.github.com/en/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace

## Временный Actions-стенд

Владелец один раз задаёт **Settings → Secrets and variables → Actions**:

- `LIVE_LAB_ALLOWED_EMAIL`: один точный mailbox для входа через одноразовый PIN.
  Не wildcard и не список адресов; значение не публикуется в summary.
- `LIVE_LAB_PASSWORD`: отдельный пароль 16–128 символов без перевода строки.
  Это пароль demo-приложения после внешнего email-gate, не токен GitHub.

`Live laboratory → Run workflow → main`, длительность 15/30/60 минут.
Workflow не принимает PR-код и не выполняется по push/schedule. До попадания
файла в default branch ручная кнопка GitHub может быть недоступна. Никакие
секреты не нужны для offline-тестов или devcontainer-проверки.

Стартовый шаг собирает один образ, создаёт новый случайный DB-пароль и отдельные
тома, проверяет настоящий сценарий авторизации, затем запускает cloudflared
с **обязательным `--allowed-mail`**. До публикации ссылки проверяется redirect
анонимного запроса к `https://login.trycloudflare.com/`. Generic 403, 502 и
просто случайный URL не считаются доказательством защиты. При ошибке нет
fallback на незакрытый туннель. Во время сессии защита проверяется снова.

URL и точное время окончания выводятся в **Start and open the protected lab**
как notice, сохраняются в summary и `live-lab-link-*`. Summary может быть
показан лишь после окончания job: во время работы открывайте уже завершённый
стартовый шаг. Доступ живёт только пока работает **Keep the session available**.
Сначала введите свой email/PIN Cloudflare, затем логин demo-пользователя и
известный вам `LIVE_LAB_PASSWORD`. GitHub Actions не отправляет вам пароль.

`Cancel workflow`, истечение времени или отказ проверки защиты закрывают
туннель и удаляют только project этой сессии. Автоматического продления нет.
Логи cloudflared и файлы секретов не выгружаются в artifacts. Артефакт содержит
только источник, image ID, URL и срок действия; ссылка после завершения мертва.
Если runner аварийно потерян, его процесс/VM не является постоянным хостом;
успешное выполнение cleanup при таком отказе не обещается.

Cloudflare — дополнительный внешний обработчик: ему передаются выбранный email
для ограничения доступа и трафик демонстрации. Только вымышленные данные.
Официальная инструкция: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
Pinned client: 2026.10.7, официальный linux-amd64, SHA-256 проверяется до запуска.
При недоступности внешнего сервиса сценарий завершается ошибкой, не ослабляет доступ.

## Границы доказательств

`tests/live_lab.rs` проверяет отказ при пустых/широких приглашениях, неверной
длительности и ложной «защите» по 200/403/502 либо чужому redirect-domain.
`Browser lab verification` строит реальный devcontainer через официальный CLI,
запускает lifecycle, проверяет настоящий backend, повторный start и stop/start.
Это не доказывает созданный GitHub Codespace, браузерную сессию владельца,
работоспособность почтового PIN или отсутствие ограничений его организации.

Короткая negative-проверка настоящего tunnel использует `test@example.invalid`:
только анонимный GET, без отправки PIN. Она подтверждает отказ анонимному клиенту,
не успешный вход человека. Два авторских прогона такой проверки выполнены на
рабочей ветке. В итоговом workflow повтор доступен только вручную на main,
с явным `verify_tunnel=true`; обычные push/PR никогда не открывают туннели.
Тест не использует репозиторные секреты и ограничен одной минутой сессии.
Доказательства разделяют локальную приёмку backend, анонимный email-gate
и непроверенный authenticated browser login.

Постоянные staging/stable остаются отдельным этапом. Эти лаборатории
дают путь просмотра и ручного тестирования без ожидания их развёртывания.
